# Голосовые заметки в kb

## Триггер

**Три способа распознать голосовую заметку:**

### 1. Маркер gateway (автоматически)
Gateway оборачивает транскрипцию в маркер. Если в сообщении виден любой из
этих паттернов — это голосовая заметка, НЕ диалог:

`[The user sent a voice message~ Here's what they said: "..."]`
- `[The user sent a voice message but I had trouble transcribing it~ ...]` — ошибка STT
- `[The user sent a voice message but I can't listen to it right now — no STT provider is configured.]` — нет STT

Gateway также шлёт эхо `🎙️ "..."` в чат — это подтверждение успешной транскрипции.

### 2. Вербальный маркер (пользователь произносит)
Если сообщение начинается со слова **«Заметка»** (или «Заметка,», «Заметка:») —
это голосовая заметка для сохранения в kb. Даже если нет маркера gateway.

### 3. Аудио-документ (файл с диктофона)
Если в сообщении виден любой из маркеров ниже — это аудио-файл, отправленный
как документ, НЕ диалог:

- `[The user sent an audio file attachment: ... It is saved at: /path/to/file.aac ...]`
- `[User sent audio: /path/to/file.aac]`
- `[The user sent a voice message: /path/to/file.aac]`

**Действие:** сразу запустить STT + pipeline асинхронно:
```bash
cd /home/ubuntu/.hermes/hermes-agent && python3 -c "
from tools.transcription_tools import transcribe_audio
import subprocess, sys
result = transcribe_audio('/путь/к/файлу.aac')
if result['success']:
    transcript = result['transcript']
    proc = subprocess.Popen(['python3', '/home/ubuntu/bin/pipelines/voice-to-kb.py'], stdin=subprocess.PIPE, text=True)
    proc.communicate(input=transcript)
    print(f'OK: {transcript[:50]}...')
else:
    print(f'ERROR: {result.get(\"error\", \"unknown\")}')
" 2>/dev/null
```
Запускать через `terminal(background=true, notify_on_complete=true)`.
Сразу ответить пользователю: `⏳ Обрабатываю аудио-файл...`
По `notify_on_complete` ответить в чат результатом stdout: `✅ Готово: <коммит>` или stderr как ошибку.

**Нестабильность маркеров:** пустые аудио-документы не всегда получают маркер. Если `msg=''` — проверять `gateway.log` на `Cached user document` с audio-расширением.

**Все голосовые сообщения = заметки в kb.** Команды и задачи пользователь пишет текстом.

**КРИТИЧЕСКИ ВАЖНО:** при получении маркера `[The user sent a voice message~...]`
агент НЕ отвечает на содержание транскрипции. Не комментирует, не обсуждает,
не задаёт вопросов. Сразу переходит к сохранению в kb.

## Процедура

При получении голосовой транскрипции:

### 1. Подготовить текст

Прочитать транскрипцию. **Сохранять оригинальный текст как есть** — не переписывать, не перефразировать, не «улучшать». Убрать:
- Служебные маркеры gateway: `[The user sent a voice message~ ...]`, кавычки вокруг текста
- Вербальный маркер: если сообщение начинается с «Заметка» / «Заметка,» / «Заметка:» — убрать это слово и разделитель (двоеточие, запятую, пробел)

Авторский стиль, тон, интонация — всё остаётся.

Сформулировать только **краткое название** (5–10 слов, суть мысли) — оно пойдёт в filename и title.

### 2. Запустить pipeline в фоне

```bash
echo '<текст заметки>' | python3 ~/bin/pipelines/voice-to-kb.py
```

Pipeline сам:
- Запишет файл в `kb/fleeting/` с UUIDv7 и фронтматтером
- Закоммитит и запушит
- Напечатает `OK: <хеш>` в stdout

Запускать через `terminal(background=true, notify_on_complete=true)`.

### 3. Ответить пользователю

Сразу (не ждать завершения):

```
📝 <Название>
⏳ Сохраняю в kb...
```

По завершении фонового процесса агент получит уведомление и ответит:

```
✅ Закоммичено: <хеш>
```

## Проверка перед записью

Перед созданием файла проверить `search_files` по `fleeting/`, нет ли уже
заметки с сегодняшней датой и похожим названием. Если есть — дополнить
существующую через `patch`, а не создавать дубликат.

## Питфолы

- Не писать «Голосовая заметка» в заголовке — это и так понятно из source: voice.
- Не спрашивать «Сохранить?» — просто сохранять.
- Если git push падает — сообщить об ошибке, но не повторять автоматически.
- UUIDv7 через `uuid.uuid1()` — достаточно для уникальности.
- STT синхронная — пока whisper работает, сессия заблокирована (10–30 сек на CPU).
- **Аудио-документы НЕ проходят STT автоматически.** Gateway запускает STT только для `msg.voice` и `msg.audio`. Файлы с диктофона (`.aac`, `.mp3`, `.m4a`) отправляются как документы и кешируются без транскрипции. **Решение:** запускать STT вручную через `transcribe_audio()` из `tools/transcription_tools` (см. триггер #3 в секции «Триггер»).
- **Пустые аудио-документы теперь должны приходить как audio attachment.** Gateway помечает `.aac/.m4a/.mp3/...` documents как `MessageType.AUDIO`, поэтому агент получает путь в note `[The user sent an audio file attachment: ...]`. Не читать `gateway.log` как основной механизм.
- **Предпочтение пользователя: запись на диктофон.** Пользователь записывает на диктофон телефона, затем шлёт файл в Telegram как документ. Это удобнее, чем запись в Telegram (не блокирует экран, не прерывается случайным касанием). Приёмка таких файлов через триггер #3.
- **Уведомления через агента, не через Bot API.** Пользователь не хочет дублирования уведомлений. Pipeline печатает результат в stdout, агент при получении `notify_on_complete` отвечает пользователю.
- **Typing indicator — root cause и путь к фиксу.** См. `references/typing-indicator-architecture.md` для полного анализа.
  - **Причина:** `telegram.py:2578` вызывает `send_typing()` после КАЖДОГО `send()` — чтобы typing не пропадал между промежуточными сообщениями. Telegram Bot API не имеет действия «отменить печатание». Когда агент завершает ход, `_stop_typing_task()` отменяет цикл `_keep_typing`, но последний `sendTyping` протухает только через ~5 секунд. Если после этого что-то ещё вызывает `send()` — typing перезапускается заново.
  - **Путь к фиксу:** убрать `send_typing()` из `telegram.py:send()`, оставить только в `_keep_typing` цикле. Тогда typing живёт ровно столько, сколько работает агент. Потенциальный побочный эффект: typing будет пропадать между промежуточными сообщениями (прогресс-репорты). Проверить, насколько это заметно.
  - **Не пытаться фиксить сейчас** — это upstream патч, требует понимания всех потребителей `send_typing` в `send()`.
- См. `references/kb-conventions.md` для структуры репы и формата frontmatter.
- См. `references/gateway-voice-format.md` для точных паттернов gateway.
- См. `references/audio-document-gap.md` для подробностей о проблеме аудио-документов и workaround.
- **Паттерн gateway: тильда `~`, не точка `.`.** Формат `[The user sent a voice message~ Here's...]`. Если паттерн не совпадает — скилл не сработает.
- **Не отвечать на содержание транскрипции.** Даже если кажется что пользователь задаёт вопрос — он говорит в телефон, а не печатает. Сохранять и молчать.
